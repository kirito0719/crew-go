# ISSUE-100：并发任务的历史压缩边界缺少源水位

状态：待决；2026-11-23 在上下文恢复独立审计中复现，属于既有 AutoCompact 历史边界发布契约。

## 触发与影响

同一 owner、thread、历史成员位置内，任务 A 读完历史并生成摘要，最后一次模型调用暂时阻塞；任务 B 在此期间完成并追加自己的输入和结果。A 随后写入自包含压缩边界。下一次任务读取历史遇到 A 的边界即停止向前扫描，可能看不到 B 的记录，而原始 HistoryStore 仍保留它们。

实际探针对照：不发布新快照时原历史与下一任务均能看到 B；发布晚到快照时原历史有 B、下一任务看不到 B，三个任务均正常返回。

## 当前边界

`ContextRecovery` 不发布跨 Run 历史边界，跨 Run 重读完整历史并重新折叠；继承已有摘要也不获得发布资格。生产并发回归同时覆盖空历史和已有 AutoCompact 摘要：[`TestContextRecoveryConcurrentTaskKeepsNewHistory`](../../agent_v2/context_recovery_test.go)。原 AutoCompact 的新摘要发布仍有上述限制。

## 完成条件

确定快照源水位与写入归属，只跳过真正被快照覆盖的原始记录，保留期间的并发追加。方案需覆盖异步历史写入器、部分写入、旧边界、重复消息记录、嵌套成员及实际部署后端。

`HistoryCursor` 不透明，`HistoryPage.Start` 仅标页首；消息 ID 可重复，未必在原始消息对象上生成。不能把消息 ID 集合或 cursor 数字大小当作精确覆盖证明。持久化接口变化前应先比较所有 backend 可共同满足的语义。
